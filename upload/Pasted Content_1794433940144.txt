## PART 3. THE COPY DIET (the client says there is far too much text)

**Rule: if the user can already see it or can guess it, delete it.**

### 3.1 Hard rules
1. **No description under any page title, section title, card title, table, dialog title or empty state**, except a dialog that is destructive or irreversible, or a form field whose purpose is not obvious.
2. Titles are 1 to 3 words, sentence case. ("Orders", "Request a product", "Recent orders".)
3. Buttons are verb or verb + noun: "Submit order", "Reorder", "Request a quote". Never "Click here", never "Get started".
4. Empty states: one short line and one button. Maximum 8 words in the line.
5. Toasts: title only, 1 to 4 words ("Order submitted", "Saved"). Add a description only for errors, and then say what to do.
6. Table column headers: 1 word where possible.
7. **No em dashes (—) and no en dashes in UI copy.** Use a period, a comma, or restructure.
8. Banned words and phrases anywhere in the UI: "at a glance", "in one place", "seamless", "effortless", "quiet", "control room", "intelligence", "professionally", "streamline", "powerful", "everything you need", "stay on top of", "your account at a glance", "Here's an overview", "newest first", "work best".
9. Dates and numbers speak for themselves. "Est. delivery Thu 14 Nov", not "Your estimated delivery date is".
10. Inputs use placeholder only when it adds an example ("e.g. 10 x 10 x 5 cm"). Never repeat the label.

### 3.2 Before and after (apply the same logic everywhere else)

## PART 5. MAKING IT VISUALLY STUNNING

A premium feel comes from **real imagery, tight alignment, and restraint**, not decoration.

### 5.1 Product imagery: isometric renders (biggest visual upgrade)
Replace `product-artwork.tsx` line-art with **procedurally generated isometric renders**, so every product looks like a studio shot.

1. Create `src/components/shared/iso.tsx` with SVG helpers:
   - `iso(x, y, z)` returns screen coordinates using `X = (x - y) * cos(30deg) * s`, `Y = (x + y) * sin(30deg) * s - z * s`.
   - `<Prism w d h tone/>` draws a box with three polygons: **top** (lightest), **left** (mid), **right** (darkest). Optional `lid` offset and `open` flaps for cartons.
   - `<Cylinder r h tone/>` with elliptical top, side body with a linear gradient from light to dark, optional `taper` for cups and bowls.
   - `<GroundShadow/>`: blurred ellipse (`feGaussianBlur stdDeviation=6`, black at 10% opacity) under the object.
2. Light comes from the top-left. Three-tone shading per hue: top L=0.95, left L=0.86, right L=0.76 (oklch, chroma ~0.03).
3. Compose each product from the primitives: carton (open-flap box), pizza box (flat wide prism with lid line), clamshell (hinged prism), cup (tapered cylinder + lid), bowl (wide tapered cylinder), deli tub (short tapered cylinder + lid), kraft bag (tall prism with fold line and handle), soup container, wrap/film roll (cylinder on its side), custom mailer (prism with printed panel).
4. Add a "print" detail on the front face: a small lighter rectangle or circle as a placeholder logo, no text.
5. Colour families: kraft (cartons, pizza boxes, bags), clear/grey (PET, PP), white (cups, bowls). Tile background: `radial-gradient(circle at 50% 30%, #fff, oklch(0.965 0.004 250))` for white and grey; `--kraft-soft` for kraft.
6. Keep the same props (`sku`, `compact`, `className`) so no call sites change. Rendered 4:3 on cards, 1:1 in table thumbnails (48px).

### 5.2 Surfaces and depth
- Canvas `--background`. Surfaces `--card` with 1px `--border`. Nothing else. No gradients in the UI chrome, no glow, no blur except the sticky top bar (`backdrop-blur-sm` over 85% white).
- Hover on interactive cards: border colour goes to `oklch(0.85 0.01 258)` and `--elev-md` appears. Nothing moves.

### 5.3 Dashboard layout (exact)
1. Greeting (`text-xl`) left, primary "Browse products" + outline "Request a product" right.
2. **KPI row:** four stats in one surface divided by hairlines. Each cell: label (`text-sm`, muted) above number (`text-2xl`, ink). Clickable. No icons, no hints, no delta unless the DTO provides it.
3. Two columns (8/4):
   - Left: "Active orders" as a list of **order progress rows**: order number, items summary, a thin 4px progress bar (width = stage fraction, cobalt), status label, estimated delivery. This replaces the generic table and is the most useful thing a customer sees. Below it, "Reorder" as a horizontal row of up to 4 compact product tiles (isometric thumbnail, name, last quantity, "Reorder" button).
   - Right: "Needs your attention" (change requests awaiting reply, quotes to accept, unread messages), then "Recent activity" as a plain list with relative times. No timeline spine, no icon circles.

### 5.4 Login (exact)
- Two columns 50/50. Left: solid deep ink (`--sidebar`) panel with the ClientHub mark top-left, a **composition of 4 to 5 isometric packaging objects** (carton, pizza box, cup, bag) arranged on a subtle isometric grid floor (1px lines at 6% white), headline `text-2xl` "Packaging orders, simplified" (sentence case, no period, no sub-paragraph), nothing else. No blobs, no stripes, no mock timeline card.
- Right: form on white. "Sign in to ClientHub" (`text-xl`), email, password (with show toggle), full-width cobalt button "Sign in", "Forgot password?" link. Demo accounts underneath as a compact 4-row list (org + role). Remove the "Remember me for 30 days" label length ("Keep me signed in"). Remove the theme toggle.
- Mobile: single column, mark on top.

### 5.5 Shell details
- Brand mark + "ClientHub" in the sidebar top (white). Under it nothing (drop the "Jeffery Group Ltd." sub-label; put the company name in the avatar menu header).
- Avatar: 32px circle, initials, `--primary` background.

## PART 6. NEW FEATURE: "REQUEST A PRODUCT WE DON'T CARRY"

Customers must be able to ask Jeffery Group for a product that is not in their catalogue. This reuses the quotation system (so admins already have a workflow) and adds a clear, friendly entry point.

### 6.1 Customer flow

**Entry points (all open the same right-side Sheet `ProductRequestSheet`):**
1. Catalogue: the **last tile in the grid** (and the last row in table view) is a dashed-border card with a plus icon: "Can't find it? Request a product". Always visible.
2. Catalogue search with **zero results**: the empty state's primary button is `Request "{query}"` with the query prefilled as the product name.
3. Dashboard header: "Request a product" outline button.
4. Quotes view header: primary button "Request a product" (the existing "New quote" dialog stays for price quotes on existing products; rename its button "Request a quote").
5. Top-bar `+` menu is **not** needed; do not add it.

**The sheet (480px, one scroll, three sections with plain `text-md` titles, no step numbers):**

1. **Product**
   - Product name* (text)
   - Type* (select: Box or carton, Pizza box, Bag, Cup or lid, Container or tub, Film or wrap, Mailer, Label or sticker, Other)
   - Description (textarea, 3 rows, placeholder "What is it used for?")
   - Reference file (optional): only if an existing upload path can be reused without new backend work; otherwise omit and list it in the final report as a follow-up.
2. **Specification**
   - Size: three small numeric inputs L, W, H plus a unit select (mm, cm, in)
   - Material (select: Kraft paper, Corrugated board, Paperboard, PET, PP, Other)
   - Printing (select: None, 1 colour, 2 colours, Full colour)
   - Food contact (switch, default on)
3. **Order**
   - Quantity per order* (number)
   - Expected yearly volume (number, optional)
   - Needed by (date picker, optional)
   - Delivery address (select of the organisation's saved addresses, default address preselected)

Footer: "Cancel" and a primary "Send request". On success: close the sheet, toast "Request sent", navigate to the new quote's detail (`quote-detail`) so the customer sees it immediately.

Validation: only the starred fields are required. Errors inline. Do not block on optional fields.

### 6.2 Data mapping (no new endpoint)
Submit to the existing `POST /api/customer/quotations`. Map fields onto the existing columns:
- `title` = product name
- `category` = Type
- `productName` = product name
- `dimensions` = "L x W x H unit"
- `material`, `printing` as chosen
- `quantity` = quantity per order (string, as the column is a string)
- `neededBy`, `destination` (selected address as a one-line string)
- `specs` = description + "Food contact: yes/no" + "Yearly volume: N"

**One allowed schema change:** add `kind String @default("QUOTE")` to `model Quotation` in `prisma/schema.prisma` (values `QUOTE` or `NEW_PRODUCT`). Run `bun run db:push` and `bun run db:generate`. Update `src/app/api/customer/_validation.ts` (optional `kind` enum, default `QUOTE`), the DTO types in `src/types/index.ts` (add `kind` to the quotation list and detail DTOs), `serialize.ts`, and the create route so it stores `kind`. The new sheet sends `kind: "NEW_PRODUCT"`. The create route must also send the admin notification with the title "New product request <quote#>" when `kind` is `NEW_PRODUCT`. Do not touch seed data except to set `kind` for nothing (defaults cover it).

### 6.3 Presentation
- Quotes list (customer and admin): rows with `kind === "NEW_PRODUCT"` show a small neutral tag "New product" next to the title. Add a filter chip "New products" to the admin quotes toolbar.
- Quote detail for `NEW_PRODUCT`: heading "Product request", spec shown as a clean two-column key/value list, the same status timeline as quotes, and the same Accept, Revise, Decline actions once issued.

### 6.4 Admin follow-through
- Admin quote detail, for `NEW_PRODUCT` requests: a secondary button **"Add to catalogue"** that opens the existing product-create form (from `admin-products-view.tsx`) **prefilled** with name, category match, and description. After the product is created, grant the requesting organisation access using the existing `POST /api/admin/products/access` endpoint, and post a customer notification "Your requested product is now in your catalogue" (existing notification helper). If wiring the prefill requires large changes to `admin-products-view.tsx`, extract the create form into a small shared component first, then reuse it; do not duplicate it.
- Attention view surfaces new product requests like any quote request.
